## 取长补短的实现方向

保留 agy-switch 的客户端适配、任务活跃检查、切换协调器、CLI 和桌面后台调度。当前已把身份观察拆为单独模块，把界面账号模型与持久化凭据模型分开，并统一手动与自动切换的写入入口。

Antigravity-Manager 的 API 网关有独立的协议映射、令牌管理、限流和会话调度模块。后续接入时应复用账号核心，通过独立网关服务管理请求账号池；API 请求挑选账号不应触发桌面客户端退出或切换。网关应由用户显式启用，单独配置监听地址、访问密钥与运行状态。

当前没有移植网关服务，也没有声明两份上游项目已完整合并。下一阶段的接口应先覆盖「获取可用账号凭据、反馈额度与请求结果」，再接入协议转换和流式响应。

## 仍需独立处理的边界

- 本地账号 JSON 中的凭据仍沿用上游存储方式。本轮减少了界面返回内容，没有完成系统凭据库迁移或落盘加密。
- 多个数据库、文件及系统凭据库的切换尚不是完整的跨存储事务。现在能报告失败，设备 JSON 在数据库同步失败时可恢复；不能据此宣称所有切换失败都已整体回滚。
- 当前原始指纹备份仍是全局首份基线。多个独立客户端使用不同原始指纹时，后续应增加按客户端和存储路径区分的备份与恢复。
- 本轮测试覆盖合成数据的业务行为。Windows 原生凭据库、客户端关闭与重启、真实网络授权仍需在专用测试账号环境中验收。

改动前的源码备份位于 `.repair/baseline-20261117`，本地验证日志位于 `.repair`；这些内容已加入忽略规则。
